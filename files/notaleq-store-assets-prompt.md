# Claude Design Brief — Notaleq Store Marketing Assets (Phone Screenshots + Feature Graphic)

This builds on the existing Notaleq design system, screens, and logo. Produce
**store listing marketing assets**: a set of **phone-mockup screenshots** and a
**feature graphic** — each in **two language versions: Arabic and English**.

Stay 100% consistent with the brand: same accent and palette, same calm/precise
personality, the new logo where a brand mark appears.

**Brand accent:** `#0E7A6B` (light) / `#21A78F` (dark). Use the full Notaleq
palette already established. Numbers must keep their **tabular figures**.

---

## 1. What a "phone screenshot" looks like here (the format)

Each phone screenshot is a **marketing composition**, not a raw screen grab:

- A realistic **phone device mockup** (modern frame, slim bezels, rounded
  corners) with an **actual Notaleq app screen placed inside the screen area** —
  pulled from the screens you already designed.
- Above the mockup, a **short headline** (one line, max ~6 words) that sells the
  feature shown in that screenshot.
- A **branded background** using the palette, consistent across the whole set so
  the listing looks like one cohesive system (same background treatment, same
  headline type/size, same device frame, same margins on every screenshot).
- Keep text minimal and honest: **no "Install now" / "Try now" CTAs, no ranking
  or performance claims, no fake UI** — Google rejects those. Taglines should stay
  light (roughly ≤ 20% of the image).

**RTL/LTR:** Arabic versions are right-to-left (headline right-aligned, layout
mirrored where it makes sense and Arabic app screen inside). English versions are
left-to-right with the English-localized app screen inside.

For each feature: drop the named app screen into the mockup, add the headline.
Produce **both an Arabic version and an English version** of every one. The

it short.

Order the set so the **two Calculator screenshots come first** (they're the hero
of the app), then History, then dark mode, then currency, then language.

## 3. Feature graphic (Play Store) — Arabic + English

A single **1024 × 500 px** banner (Play Store requires it; the App Store has no
equivalent). Produce an **Arabic version and an English version**.

- Brand-forward: the **Notaleq logo/mark** + a short tagline + a hint of the
  product (e.g. a glimpse of the ledger with its running total).
- Keep critical elements **away from the edges** (Play may overlay/crop), and away
  from the far-left where the app icon can sit on some surfaces.
- Suggested tagline — EN: "The ledger calculator for everyday money."
  AR: "آلة حاسبة بدفتر — لحسابات يومك."

---

## 4. Exact sizes (export to these)

**Phone screenshots** — design at the App Store master size, then also export the
Play size (the two stores use different aspect ratios, so each screenshot needs
both):

| Store | Size (px) | Format |
|---|---|---|
| Apple App Store — iPhone 6.9" (primary) | **1320 × 2868** (portrait) | PNG/JPEG, sRGB, **no transparency** |
| Apple App Store — iPhone 6.5" (optional extra slot) | 1242 × 2688 | same |
| Google Play — phone | **1080 × 1920** (portrait, 9:16) | JPEG / 24-bit PNG, **no alpha**, < 8 MB |

**Feature graphic (Play only):** **1024 × 500 px**, JPEG / 24-bit PNG, no alpha.

If producing every size for every screenshot is too much at once, prioritize the
**App Store 1320×2868** set first (Arabic + English), then the **Play 1080×1920**
set, keeping the layout/safe margins so the same composition reflows cleanly
between the two ratios.

## 5. Deliverables checklist

- 12 phone screenshots = 6 features × (Arabic + English), at the store sizes above.
- 2 feature graphics (1024×500) = Arabic + English.
- One consistent visual system across the entire set (background, headline style,
  device frame, margins), tied to the Notaleq brand and palette.
- English versions fully localized (UI inside the mockup + headline), not just
  translated headlines over Arabic screens.
